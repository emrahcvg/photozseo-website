2026 年には、500 個の製品を Shopify にプッシュするには 2 つの方法があります。管理者 UI を介して CSV をアップロードするか、管理者 GraphQL/REST エンドポイントを介して 500 個の API 呼び出しを送信します。どちらも機能します。規模も失敗も異なり、適した販売者も異なります。

この記事では、両方のパスを分析し、比較表を作成し、Shopify CSV 列リファレンスを詳しく説明し、photoZseo を含むほとんどの製品ツールが直接 API 統合ではなくファイル エクスポートを選択する理由を説明します。

## Shopify への 2 つのパス

| パス | それは何ですか | 認証 | スピード | レート制限 |
|------|-----------|------|-------|------------|
| CSVインポート | Shopify管理→製品→インポートを通じてファイルをアップロードします | なし (ログインした管理者) | ~500 製品 / 5 分 | なし — Shopify キュー |
| REST管理API | 製品またはリソースごとの HTTP POST | プライベート/カスタムアプリ経由のアクセストークン | ～2製品/秒 | 標準で 2 コール/秒、4 プラス |
| GraphQL 管理 API | 単一エンドポイント、一括変異 | アクセストークン | 一括操作で 1 秒あたり最大 5 ～ 10 製品 | 標準 50 ポイント/秒、100 ポイント/秒 |
| 一括操作 API | 大規模なジョブの非同期 GraphQL バルク | アクセストークン + ポーリング | 非同期、完了までに数時間 | 1回の操作としてカウント |

見出し: レート制限が始まると、CSV は人々が思っているよりも高速ですが、API は人々が思っているよりも遅くなります。

## コスト比較

| 要素 | CSVアップロード | 管理者API |
|--------|-----------|-----------|
| セットアップ時間 | 0分 — Shopifyに内蔵 | アプリの登録、トークンの生成、クライアントの作成に 1 ～ 4 時間 |
| 輸入ごとのコスト | 無料 | 無料（レート制限内） |
| 速度 (100 SKU) | アップロードに 1 ～ 2 分 + 処理に 2 ～ 5 分 | 1 ～ 2 分の API + 継続的なレート制限バックオフ |
| 速度 (10,000 SKU) | アップロード 10 分 + 処理 30 ～ 60 分 | レート制限に応じて 30 分から 4 時間 |
| エラー回復 | Shopify は、失敗した行を含む詳細な CSV を返します。 | API は呼び出しごとのエラーを返します - コードは収集して再試行する必要があります |
| 監査証跡 | CSVファイル自体が記録です | 開発者が実装する必要があるカスタム ログ ファイル |
| 復帰可能性 | 以前の CSV を再アップロードする | リソースごとのカスタム ロールバック ロジック |
| 認証リスク | なし - 漏洩するトークンなし | トークンは保存、ローテーション、監査される必要がある |
| 必要なスキル | スプレッドシートのスキル | ソフトウェアエンジニアリング |
| 失敗のコスト | 不適切な CSV により、一括削除できる 500 個の商品が追加される | 不正な API ループはレート制限に達し、実行中に失敗する可能性があります |

Shopify ストア、製品写真が満載の iPhone、および 200 個の SKU を立ち上げるインディーズ販売者の場合、CSV パスの方が高速、安価、安全、そして元に戻すことができます。

## CSV が勝ったとき

- 持っている商品は 1,000 未満です。 CSV はこのバッチ サイズを適切に処理します。
- 継続的なインベントリ同期ではなく、定期的な起動を実行します。四半期ごとのカタログ更新は CSV 形式です。
- コードを書かずに監査証跡を取得したい。すべての CSV アップロードは、Dropbox/iCloud/Google ドライブに保存できるファイルです。
- API トークンを管理したくない。アプリをインストールしたり、トークンをローテーションしたりする必要はありません。
- 変更を公開する前にプレビューしたいと考えています。 Shopify の CSV インポートでは、「すべての販売チャネルに製品を公開する」のチェックを外した場合、変更が適用される前の影響を受ける製品が表示されます。
- 複数の店舗をまたがって営業しているんですね。同じ CSV がどの Shopify ストアでも機能します。同じ API クライアントにはストアごとにトークンが必要です。

## API が勝ったとき

- 10,000 以上の製品があり、毎晩実行されます。
- 倉庫システムまたは ERP からのリアルタイムの在庫更新が必要です。
- データを往復する必要があるカスタム POS、3PL、または ERP に接続します。
- 統合を維持するためのエンジニアリング リソースがあります。
- B2B で事業を行っており、1 分未満の反映を必要とする頻繁な価格変更があります。

ほとんどのインディーズ販売者にとって、2026 年の変曲点は、週次売上高で約 2,000 ～ 3,000 SKU になります。その下にCSVがあります。その上に、API または Make、Zapier、Shopify Flow、n8n などのマネージド iPaaS があります。

## Shopify CSV 列リファレンス

2026 CSV には 53 列が同梱されています。影響の大きいサブセット:

| カラム | 必須 | 注意事項 |
|--------|----------|-------|
| ハンドル | はい | URL スラッグ。決定的重複排除キー - 同じハンドル = 同じ製品。 |
| タイトル | はい | 製品タイトル、プレーンテキスト。 |
| 本文（HTML） | 推奨 | 完全な説明。HTML を使用できます。 |
| ベンダー | はい | ブランドまたはメーカー。 |
| 製品カテゴリー | はい | Shopify の標準分類にマッピングされます。 |
| タグ | 推奨 | カンマ区切りで、コレクションとフィルターを駆動します。 |
| 発行済み | はい | 店頭の可視性については TRUE/FALSE。 |
| バリエーション SKU / グラム数 / 価格 / バーコード | 推奨 | バリアントごとのインベントリおよび識別子フィールド。 |
| 画像ソース | はい | 製品画像の公開URL。 |
| 画像の代替テキスト | 強くお勧めします | 画像検索と AI の概要の SEO フィールド。 |
| SEOタイトル/SEO説明 | オプション | ページタイトルとメタディスクリプションはオーバーライドされます。 |
| 状態 | はい | 「アクティブ」、「ドラフト」、または「アーカイブ済み」。 |

残りの 30 以上の列は、メタフィールド、Google Shopping フィールド、および税地域列です。インディーズ販売者は、国際的に展開するまでこれらを無視できます。

## CSV内の画像SEO

写真のランクを決定する 2 つの列は、Image Src と Image Alt Text です。

- 画像ソースはパブリック URL である必要があります。 Shopify が CSV を取り込むときは、イメージにアクセスできる必要があります。ファイルがプライベート CDN またはトークンで保護されたバケットの背後にある場合、インポートはサイレントに失敗します。
- 画像代替テキストはフィールド Google 画像検索、Pinterest および AI 概要の引用が読み取られます。 100 文字以内にしてください。ブランドではなく製品でリードしましょう。

インディーズ販売者によくある失敗: Image Src 列は入力されているが、Image Alt Text 列が空白の状態で、CSV 経由で 200 個の商品をアップロードします。 Shopify は喜んで写真をインポートします。ストアは画像の SEO 面全体を失います。

## photoZseoのアプローチ

photoZseo は、Shopify 対応ファイルを 3 つの形式でエクスポートします。

1. CSV — 53 列を含む正規の Shopify 製品インポート形式。販売者はそれを Shopify Admin → Products → Import にドロップします。
2. XLSX (Excel) — アップロード前にスプレッドシートで編集する販売者向け。画像サムネイルが埋め込まれているため、行が視覚的にプレビューされます。
3. DOCX — ドキュメント、サプライヤーの提案、またはカタログの印刷用。

このツールは、Shopify Admin API に直接接続しません。 「Connect Shopify」ボタン、トークンストレージ、リアルタイムプッシュはありません。販売者は最新情報を常に把握します。CSV を Excel/Numbers で確認し、Shopify 管理者を通じてアップロードし、ファイルを監査証跡として保存します。

これはデザイン上の選択です。機能フラグ `shopifyAPIEnabled` は、2026 リリースでは `false` として出荷されます。推論:

- 販売者は変更内容を完全に制御できます。自動化されたジョブが不正な形式のバッチをプッシュすることはありません。
- 監査証跡はファイルです。すべてのインポートは CSV であり、販売者は再アップロード、アーカイブ、または元に戻すことができます。
- トークンの攻撃面はありません。アプリが Shopify 資格情報を保持することはありません。
- クロスプラットフォームの一貫性。同じ CSV が Shopify にアップロードされ、同じ XLSX が Amazon および Etsy にフィードされ、同じ DOCX がカタログに出力されます。 1 つのワークフロー、10 の宛先。

継続的な API 同期を必要とする販売者 (たとえば、3PL を使用する Shopify Plus オペレーター) にとって、専用のミドルウェア (Shopify Flow、Make、n8n) が適切なツールです。発売四半期と 200 製品を扱うインディーズ販売者にとって、CSV パスは永続的な答えです。

## 5 ステップの Shopify 起動ワークフロー

1. iPhoneで商品写真を撮影します。白背景、sRGB、2000×2000。
2. 製品ごとに 13 の SEO フィールド (タイトル、スラッグ、ファイル名、カテゴリ、メタディスクリプション、完全な説明、代替テキスト、4 つのタグ、キーワード、バーコード) を自動入力します。
3. 画像ソース (CDN または Shopify 独自の画像アップロードでホストされている)、画像代替テキスト、SEO 説明など、該当する場合は 53 列すべてが入力された Shopify CSV をエクスポートします。
4. 最後にもう一度確認するために、Numbers、Excel、または Google Sheets で CSV を開いてください。
5. Shopify管理→製品→インポートでアップロードし、更新する場合は「同じハンドルを持つ既存の製品を上書きする」にチェックを入れて送信します。

販売者の製品 200 個あたりの発売時間は、数日かかる作業から 1 日の午後に短縮されます。

## 持ち帰り

2026 年、インディーズ販売者にとっての正しい Shopify インポート パスは CSV です。これは人々が想定しているよりも高速で、API よりも可逆性が高く、記録として保存できるファイルを生成します。 Admin API は、エンジニアリング主導の大規模なカタログ運用には最適なツールですが、200 SKU のストアフロントでは CSV の方が適切です。

その選択を尊重する製品ツールは、「すべてを自動化」しようとする製品ツールよりも生き残るでしょうが、最終的にはトークンを保持し、レート制限に達し、静かに在庫を破壊することになります。
